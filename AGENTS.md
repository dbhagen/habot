# AGENTS.md

Orientation for humans and AI agents working in this repository. Everything here was verified against the code on the current head (see `.obvious/local-dev.md` for recorded command output).

## What This Repo Is

HABot is a Home Assistant Supervisor add-on: a Claude-powered chat UI for inspecting, troubleshooting, and reconfiguring a Home Assistant instance through [ha-mcp](https://github.com/homeassistant-ai/ha-mcp). The default branch is **`main`**.

## Repository Map

| Path | Role |
|---|---|
| `repository.yaml` | Add-on repository manifest (name, URL, maintainer) |
| `habot/config.yaml` | Add-on metadata: options, schema, ingress (port 8099), and the version number releases bump |
| `habot/build.yaml` | Base images per arch (`ghcr.io/home-assistant/*-base:3.20`) |
| `habot/Dockerfile` | Multi-stage build on `node:22-alpine`: compile server, build frontend into `dist`, serve it from `/app/public` at runtime |
| `habot/run.sh` | Container entrypoint: reads `/data/options.json` (written by Supervisor), routes the credential by prefix, exports env vars, execs `node /app/dist/index.js` |
| `habot/server/` | Node server: Express 5 + `ws` + `better-sqlite3` + `@anthropic-ai/claude-agent-sdk` |
| `habot/frontend/` | React 19 + Vite 6 + TypeScript chat UI |
| `habot/translations/en.yaml` | Add-on UI translations |
| `habot/CHANGELOG.md` | Generated by `release.yaml` — do not hand-edit |
| `.github/workflows/ci.yaml` | PR/push gates (see below) |
| `.github/workflows/release.yaml` | Conventional-commit-driven version bump, tag, GitHub Release on push to `main` |

### Server modules (`habot/server/src/`)

- `index.ts` — HTTP wiring: `/api/health`, `/api/config` (debug flag + startup ID), `/api/chat` (curl-test endpoint that **auto-approves all tools**), `/api/entities` (proxies the Supervisor HA states API for `@` mention autocomplete), static frontend serving, startup resume check
- `agent.ts` — `AgentRunner` around the Claude Agent SDK query loop. `READ_ONLY_TOOLS` auto-approved, `DESTRUCTIVE_TOOLS` require approval, **everything else is allowed by default**. Also: restart-tool detection, stale-session retry with injected conversation history
- `websocket.ts` — WS protocol (`send_message`, `cancel`, `approve_tool`, session CRUD), message queueing while busy, approval request/response (5-minute timeout auto-denies), secret masking on everything sent or stored
- `system-prompt.ts` — agent instructions: filesystem access at `/config`, backup-before-destructive-change guideline, Supervisor backup API usage
- `database.ts` — better-sqlite3 (WAL) at `$DATA_DIR/habot.db`; sessions + messages tables with lightweight migrations
- `resume.ts` — startup check for `awaiting_resume` sessions after an HA restart; resumes with a verification prompt, 10-minute TTL, **auto-approves tools during resume**
- `config.ts` — env → `Config` (`ANTHROPIC_API_KEY`/`CLAUDE_CODE_OAUTH_TOKEN`, `HA_MCP_URL`, `CLAUDE_MODEL`, `DEBUG_LOGGING`, `DATA_DIR`, `PORT` default 8099, `SUPERVISOR_TOKEN`)
- `mask-secrets.ts` / `logger.ts` — egress secret masking patterns and debug logging
- `types.ts` — shared types including the WS message protocol

### Frontend (`habot/frontend/src/`)

- `App.tsx` — layout; persists active session and sidebar state in `localStorage`
- `hooks/useWebSocket.ts` — WS client: streaming text/tool-call state, approval requests, agent status, queue depth
- `components/` — `ApprovalPrompt` (Approve / Allow-and-always-allow / Deny / Provide instructions), `ChatView`, `ChatInput` (`@` entity mentions, image attach), `MessageBubble`, `Sidebar`, `ToolCallDisplay`, `ToolInputDisplay` (renders Edit inputs as diffs, Write as file previews)
- `utils/ingress.ts` — derives WS/API base URLs from the HA Ingress path; `utils/debug.ts` — frontend debug logging

## Commands

Run from `habot/server/` and `habot/frontend/` respectively. CI runs Node 22 (`setup-node@v4`, `node-version: 22`; the Dockerfile builds on `node:22-alpine`). All commands below were also run and passed in a Node 20.20.2 environment — recorded output in `.obvious/local-dev.md`.

```bash
# Server
cd habot/server
npm ci              # install (lockfile is committed; prefer ci over install)
npm run build       # tsc → dist/
npx tsc --noEmit    # typecheck only (what CI's lint job runs)

# Frontend
cd habot/frontend
npm ci
npm run build       # tsc -b && vite build → dist/
npx tsc --noEmit

# Dev servers (no API key needed to boot; chat errors until a key is configured)
npm run dev         # server: tsx watch src/index.ts on :8099 — curl /api/health to verify
npm run dev         # frontend: vite on :5173 — no dev proxy is configured, so API/WS calls
                    #   hit the vite origin; exercise the full UI against the built app
                    #   served by the backend (or behind HA Ingress) instead

# Validate add-on manifests (mirrors the CI validate-addon job)
python3 -c "import yaml; [yaml.safe_load(open(f)) for f in ['repository.yaml','habot/config.yaml','habot/build.yaml']]"
```

There is no test suite. CI gates are: **commitlint** (PRs, warnings fail), **build** (both packages), **lint** (`tsc --noEmit` on both packages), and **validate-addon** (YAML parse of the three manifests). Details in `.obvious/qa.md`.

## Commits & Merges

- **Conventional commits are enforced** — CI runs commitlint with `failOnWarnings: true`, and `.pre-commit-config.yaml` installs a `conventional-pre-commit` hook. Use `feat:`, `fix:`, `docs:`, `chore:`, etc.
- **Squash-merge** is the merge method for PRs.
- `release.yaml` bumps the version in `habot/config.yaml` and both `package.json` files automatically from commit types (`feat:` → minor, `fix:`/`perf:` → patch) and regenerates `habot/CHANGELOG.md`. Do not hand-edit version numbers in feature PRs.
- Do not commit to `main` directly; open a PR.

## Security

- **Never commit real API keys, OAuth tokens, or add-on option values.** Runtime secrets live in the add-on's own storage (`/data/options.json`, written by Supervisor inside the HA instance), never in git. `.env` files are gitignored, and pre-commit runs `detect-private-key`.
- When documenting the credential option, describe token *formats* only (`sk-ant-oat01-…` prefix routing in `run.sh`) — never paste real credential material.
- The server masks secrets at egress points (DB writes, WS sends) via `mask-secrets.ts`; keep new log/storage paths routed through it.
